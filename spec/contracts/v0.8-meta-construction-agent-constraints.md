This document is not a new language design overview and does not replace any
existing specification text. It is a construction-constraint document for future
engineering agents working around v0.8, especially on ordinary generic
type-style meta-function capability such as `(T Vec)`, `(T Option)`, and
`(A, B Pair)` symbol constructions.

The older formal return split (`r = ...` generated versus `r === ...`
forwarded) is superseded. Target semantics keep three operations orthogonal:
`let` creates a Symbol/member, bare `=` writes an existing place, and the return
event transfers control. The current return-cluster/`SymbolConstruction`
encoding is implementation substrate only. The semantic alias/forwarding
direction is retired, including any operator-name exception.

**Terminology (frozen).** "Symbol" (capitalized) is the semantic constructor
`S = ⟨τ?, V_S?⟩` — a value of type `symbol`. "A symbol" in natural language
below means that constructor value (the name-graph node); "binding name" /
"symbolic name" / "named binding" name the `NameBinding` concept; "the
`symbol` type" / "`x : symbol`" are the type and its classification.
`NameBinding(a)` never implies `a : symbol` (glossary: Symbol terminology).

Its core purpose is to prevent agents from implementing a local feature through
an ad hoc bypass that happens to work in isolation, while damaging the shared
semantic foundation across build/package, symbol-world, patterns-overload,
product normalization, policy-capability, meta-invocation, and mechanical
lowering.

The project takes a long-term implementation approach. Implementation may be
staged, use placeholders, or use stubs, but object boundaries and semantic
direction must not be rewritten for short-term convenience.

## 1. General Principle: Advance the Closed Loop, Not Isolated Points

Any v0.8-related implementation task must not make progress from a single module
alone. For example:

- Do not create a special execution path only for `struct`.
- Do not recognize `(T Vec)` through a name check or AST-shape check.
- Do not temporarily parse arguments only for one generic type constructor.
- Do not let the type checker, meta interpreter, policy checker, and resolver
  maintain parallel symbol tables.
- Do not let product argument reading bypass pattern / argument-shape objects.
- Do not make policy apply only at lookup time or only at execution time.
- Do not let build/package identity disappear from candidate identity, meta
  instance keys, provenance, or cache keys.

Every implementation point must be checked against this loop:

```text
build/package identity
  -> namespace graph / SymbolCell (current substrate: SymbolObject)
  -> SymbolId / PlaceId / PatternValue / TypeValueId / BorrowView
  -> ProductObject / ArgProductShape / RawArgShape / ParameterShape
     (explicit user product only; self is invocation-frame slot 0)
  -> form CallableProjection(S) = DedupCandidateIdentity(V_S ⊎ V_τ)
  -> CallSiteFamilyView(CallableProjection(S), call-site annotation)
  -> per-candidate policy/view filtering
  -> structural applicability and P2 qualification
  -> formal meta invocation
  -> ordinary semantic result across result classes
     (a multi-member meta return is currently carried as SymbolConstructionValue;
      the default result is τ)
  -> binding/install adapter (current substrate: MetaExpansionResult)
  -> NamespaceDelta atomic install
  -> generated instance identity / provenance / diagnostics
```

If one stage is not fully implemented yet, use a placeholder. The placeholder
must live in the correct object slot; it must not create a new bypass semantic.

## 2. No-Bypass Rule

Every component that needs symbols must go through the shared namespace graph
world model.

This includes, but is not limited to:

```text
resolver
early meta-function lookup
struct
assert
verify
generic type meta-functions
type checker
policy checker
seal stage
IDE index
cache layer
diagnostics
later HIR lowering
```

Forbidden:

```text
parser special-cases self / Self / return / struct / verify / () / Vec / Pair
normalizer special-cases self / Self / return / struct / verify / () / Vec / Pair
meta executor searches raw string names outside resolver
type checker maintains private global symbol map
policy checker re-resolves by string path
generic instantiation key uses source text only
core symbols are globally visible through ambient state rather than explicit graph mount
```

The only permitted bootstrap magic is a compiler-seeded core package artifact,
a default core mount, and built-in payload placeholders. Even then, those symbols
must be installed into the namespace graph and returned by the resolver as
ordinary `SymbolObject`s.

## 3. Target Stage: Ordinary Generic Type-Style Meta-Functions

For the canonical symbol-first/facet model, `compile` / `meta` result split,
rank-directed canonical identity, `struct` ownership, pure `extend`, place-level `inject`, and
binding/install boundary, see
`spec/design/symbol-world/symbol-first-meta-construction-and-pattern-injection.md`.
For extraction-view and product-return details, see
`spec/contracts/v0.8-symbolic-construction-values-and-extraction-interfaces.md`.

The current target is not full metaprogramming, full runtime overload,
value-to-value compile-time execution, a full type checker, or a full policy
lattice.

The target is the earliest restricted path toward symbol construction:

```text
compile inputs -> any declared ordinary semantic value across result classes
                  (ordinary PatternValue, complete type value tau, type ref /
                  type share borrow instance, ...), with root conservation and
                  no root authority of the compile coordinate itself
ordinary meta inputs
               -> tau (DefaultMetaResult; an explicit declared result may be a
                  symbol or another permitted result), plus authority to
                  establish and seal one navigable MetaInstanceRoot M
privileged builtins
               -> each member-specific declared result under its
                  member-specific owner rule
meta body is Normalized AST
construction is graph / delta / policy governed
```

The result split is about *rooting*, not a private construction class: `compile`
returns any declared ordinary semantic value across result classes (an ordinary
PatternValue, a complete type value `tau` — which participates in Pattern
observation through `Core(tau)` and is not itself an ordinary
PatternValue/Object — or a type ref / type share borrow instance), while an ordinary
`meta` invocation returns the
default complete type value `τ_M` of its instance (an ordinary `symbol`-typed
value only when the result is explicitly declared `symbol`); the optional
installed type core `Core(τ)` is rooted in
that invocation's `MetaInstance`. Current multi-member construction carriers do
not define another ontology
(`symbol-first-meta-construction-and-pattern-injection.md` §4.1).

Single entry / single exit and the absence of intermediate control flow are
properties of the **first implementation slice**, not language rules. The target
semantics allow static control flow, repeated local construction, and in-place
closures inside a meta body without closing the construction (§4.3.1 there); an
implementation that has not reached that point must record the gap as an
implementation limitation.

Typical targets:

```text
(T Vec)
(T Option)
(A, B Pair)
```

These targets must be implemented as ordinary graph-resolved meta callables, not
compiler special cases.

A valid generic type-style meta-function invocation should follow this flow:

```text
resolve callee symbol through namespace graph
collect callable candidates under lookup policy
form ProductObject / ArgProductShape
form per-element RawArgShape
match ParameterShape and rank-directed SymbolId / Core(tau) observation / PatternValue compatibility
check current body-entry metadata admits Meta
invoke primitive or type-to-type construction interpreter
produce the default complete type value `tau` (an ordinary `Symbol` PatternValue only for an explicitly declared `symbol` result; possibly through a transitional carrier) / Residual / Diagnostic
compute canonical meta instance key
bind to an independently resolved writable PlaceId
install NamespaceDelta atomically
retain canonical Pv:Pp on returned Val1 / Pattern entries and independent
policy pairs on returned Val2 objects; any outer binding P1 then selects a view
```

`ProductObject`, `ArgProductShape`, and `RawArgShape` describe only the
explicit user-supplied argument product. Caller self is injected by the
invocation frame into callable-frame slot 0 after callable resolution. It must
not be counted in product arity, product flattening, canonical argument
products, or meta instance keys. For every ordinary or in-place closure, the
first written formal is the explicit Pattern for slot 0 regardless of binder
spelling. Only later written formals align with explicit Product positions.

For `struct`, `pattern_owner(V)` is resolved from input navigation plus ambient
`ResolvedPatternScope` before binding. `install_place(V)` is resolved by the
outer `let` binding/injection judgment. The latter must never reroot the former.

## 4. Product Semantic Normalization Must Become a Precondition Contract

Existing public docs define surface product / pipe / call binding. v0.8 needs an
additional semantic-layer `ProductObject` normalization. This rule must not be
conflated with surface normalization.

Core rules:

```text
flatten crosses Product nodes.
flatten does not cross Expression nodes.
order is preserved.
Unit is preserved.
provenance is preserved.
```

Definition:

```text
NF_P(P) = ordered sequence of product atoms

NF_P((x1, x2, ..., xn))
  = concat(NF_item(x1), NF_item(x2), ..., NF_item(xn))

NF_item(Product p)
  = NF_P(p)

NF_item(Expression e)
  = [e]

NF_item(Unit)
  = [Unit]
```

Examples:

```text
((P, e), e)   -> (P, e, e)
((e, e), e)   -> (e, e, e)
((e, P), e)   -> (e, P, e)
(e, (P, e))   -> (e, P, e)
```

If `P` is still a product, continue flattening until the product spine contains
no exposed Product child nodes.

"Exposed P" means a Product child node directly exposed in product context. A
product already absorbed by an expression/call node is not exposed. Flattening
does not cross expressions.

Therefore:

```text
((a, b), c)
=> (a, b, c)

(a, (b, c))
=> (a, b, c)

((a |> f), (b, c))
=> (a |> f, b, c)

((a, b) |> f, c)
=> ((a, b) |> f, c)
```

Incorrect rule:

```text
((a, b) |> f, c)
=> (a, b, f, c)        // forbidden
```

This is forbidden because `(a, b) |> f` is an Expression barrier.

However, a call may locally normalize its own source product:

```text
Call(source = ((a, b), c), target = f)
=> Call(source = (a, b, c), target = f)
```

This is not crossing an Expression from the outside. It normalizes the source
product inside that call.

`ProductObject` must not silently drop `Unit`:

```text
((a,), b)
=> (a, Unit, b)

((), a)
=> (Unit, a)
```

Only a future explicit parameter expectation / extraction rule may eliminate
`Unit`. Product semantic normalization itself does not.

## 5. Minimum ProductObject / ArgProductShape Requirements

Before entering meta invocation / generic type constructors, a normalized
product must be converted into semantic objects. The recommended minimum object
layers are:

```text
NormProduct
  -> ProductObject
  -> FlattenedProductObject
  -> ArgProductShape
  -> per-element RawArgShape
```

`ProductObject` must preserve at least:

```text
original normalized product
flattened atom sequence
arity
unit positions
nested product provenance
source spans / origins
material role
```

`FlattenedProductObject` invariants:

```text
ordered sequence of atoms
no direct Product atom remains
Expression nodes are opaque
Unit is preserved
left-to-right order preserved
provenance preserved
```

`ArgProductShape` is input to candidate preparation. It is not a type-checker
result and not a runtime ABI argument list.

Each atom forms one `RawArgShape`, marking at least:

```text
is value?
explicit pass mode?
known first-order TypeValueId?
rank/type object?
namespace object?
meta object?
pattern object?
residual/runtime expression?
origin/provenance
```

Parameter matching for type-level generic callables must not trigger automatic
argument passing. Type objects, rank objects, namespace objects, meta objects,
and pattern objects are not value arguments and must not receive inserted
`copy/ref/share/move/in` actions.

Self injection is also not automatic argument passing through product shape. It
belongs to `InvocationFrame` / callable-frame construction, not to
`ProductObject`, `ArgProductShape`, or `RawArgShape`.

## 6. Symbol / Place / PatternValue Must Not Be Merged

Any generic type meta implementation must preserve:

```text
SymbolId
PlaceId
TypeValueId
PatternValue identity
ResolvedPatternScope / PatternScopeId
```

Meanings:

```text
SymbolId    = symbol object identity in the namespace graph
PlaceId     = location identity that can be created by let or updated when already present
TypeValueId = stable first-order type-root projection used by current substrate
              -- implementation/index key, not semantic equality
CanonicalTypeIdentity(tau) = Addr(Norm_type(tau))  -- snapshot identity
PatternValue identity = canonical compile-time value/pattern identity
PatternScopeId = navigable pattern-owner identity
```

`CanonicalTypeIdentity(tau)` is the whole-snapshot identity, used to tell
shared-root snapshots apart in transport and in positions the language has
independently frozen to whole-snapshot semantics. Under the minimal-change rule
(`type-values-places-and-borrow-views.md` §2.2), ordinary type-rank equality
and keying keep observing `Core(tau)=Q` by default, exactly as the old
`type = Q` rules did; `TypeValueId` is only the implementation/index projection
(first-order root), not semantic equality.

The complete target type value is an immutable closure, not bare `Q` and not a
root-to-current-Symbol lookup. It is one semantic entity with two equivalent
views: `τ ≡ DescriptionClosure(P, Val2)` — the closure view and the
`⟨P, Val2⟩` description view constrain the same entity jointly (normative:
`../design/patterns-overload/pattern-values-relational-semantics-and-extraction.md`
§15; `SameEntityTypeInvariant` in
`../design/symbol-world/type-values-places-and-borrow-views.md` §2.2):

```text
tau = <Q, V_τ>
Core(tau) = Q
CallSpace(tau) = V_τ

WellFormedTau(tau)
  iff tau = <Q, V_τ>
  and Q is a well-formed pure Object
  and V_τ is a well-formed TypeMember set
      (each F in V_τ satisfies TypeMember_Q(F))
  and AllBoundRefsBoundAndRestricted(bind alpha.⟨Norm(Q), Norm_V^alpha(V_τ)⟩)
      (every BoundRef reachable during Norm_type^alpha(Q, V_τ) is bound
       by alpha and belongs to an authorized static edge kind;
       BoundRef(alpha) notin Children_owned)
  and PatternClosureConsistent(Q, V_τ)
      -- structural, history-free; depends only on the current closure
         value, never on construction provenance
         (canonical definition:
         `../design/symbol-world/type-values-places-and-borrow-views.md` §2.2)

CompleteType(tau)  iff WellFormedTau(tau) and TypeRole(Q)
      -- equivalently TypeValueRole(tau); the type-value role

NamespaceOnly(tau)  iff WellFormedTau(tau) and NamespaceOnly(Q)
      -- NamespaceOnly(Q) formalized in
         `../design/patterns-overload/pattern-values-relational-semantics-and-extraction.md` §13:
         NamespaceRole(Q) and not HasRegisteredSelfConstruction(Q); the
         registered-self-construction witness requires an actual Val2 member:
         Val2(Q)[s] = K and ConstructEdge_P_Q(C, Q, K)

tau = bind alpha. <Q, V_τ[alpha]>
Norm_type^alpha(Self_τ) = BoundRef(alpha)

CoreAnchor(Q) = CanonicalSelfPatternRoot(Q)          -- canonical §2.1
TypeMemberScope(Q) = MemberScope(CoreAnchor(Q))

HomeEligible_Q(F)                                    -- TypeMember_Q(F)
  iff Anonymous(F)
  and DirectClassifierHome(F) = TypeMemberScope(Q)

TypeMember_τ(F)
  iff F ∈ ClassifierDomain(V_τ)
  and HomeEligible_{Core(τ)}(F)

CreateClassifier_Gamma(
  F,
  DirectClassifierHome = TypeMemberScope(Q)
)
  => CurrentAuthority_Γ(Q)

BoundRef(alpha) notin Children_owned
```

`V_τ = CallSpace(tau)` is the callspace captured into the closure value: the
direct TypeMember members placed into `tau` when it was produced
(`HomeEligible_Q(F)`, equivalently `TypeMember_Q(F)`), not a global function
of the bare core `Q`
and not a post-hoc partition of a shared Symbol space. The materialization
of `V_τ` callable members through anonymous types directly under `τ`, and the
derived closure theorems (enclosing reference, meta anchoring), are canonical
in `symbol-first-meta-construction-and-pattern-injection.md` §2.1.1. `CallSpace(tau)` is
an intrinsic property of the closure itself; it does not depend on the
current host Symbol, source binding, carrier Symbol, HomeSymbol, or any
other provenance recovery. `copy(τ)`, `extract(τ)`, and ordinary
parameter-passing of `τ` preserve `CallSpace(τ)` unchanged. Members created
under the same `Q` after formation never retroactively enter an existing
snapshot, and a copied or extracted `tau` keeps its captured `V_τ`.

Ordinary Symbol sibling operations only modify `V_S`; they do not modify the
`V_τ` already encapsulated in `τ`. Changing `V_τ` requires a semantic
operation that produces a new type value (principally `extend`). When a
Symbol carries both, `CallableProjection(S) = DedupCandidateIdentity(V_S ⊎ V_τ)` is the Symbol call
interface exposing the embedded closure callspace in one step; it does not
make `V_τ` a function of `S` or break the closure's independence.

`tau` is the complete type closure, not an Object embedding or a fourth Object
coordinate. `Q` and the members of `V_τ` remain ordinary Objects. Consumers
project `tau` as needed: ordinary Pattern/namespace observation and ordinary
type-rank equality/keying use `Core(tau)=Q`; type-as-callee candidate
acquisition uses `CallSpace(tau)=V_τ`; copying, `extend`, and `inject`
transport or transform the whole snapshot including `V_τ` (snapshot identity
`Addr(Norm_type(tau))`). `@` is the continuation-relative name-reification
operation that yields a first-class ordinary `LifetimeValue` and never a
borrow or a `type ref`. The result may use ordinary binding/passing/returning
machinery; first-class status does not imply a same-Type runtime transition,
which remains governed by the ordinary callspace materialization rule (canonical owner
`spec/design/lifetime/lifetime-policy-and-overload-boundary.md` §1–§2);
reaching the type-level place explicitly uses `t |> (type ref)` or
`(S ref).type`. `DirectClassifierHome` is immutable after
classifier creation, and selecting `TypeMemberScope(Q)` at creation requires
current construction authority for `Q`. Ordinary callable creation, navigated
`let`, copying, writing, rebinding, or namespace installation cannot forge
that home; descendant ownership is also insufficient. `Self_τ` establishes a
`SymbolicReferenceEdge` (symbolic anchoring), never an ownership or
evaluation-flow edge, so it does not establish `ActiveEvaluation` or
`OpenEvalReentry_κ` (`spec/design/symbol-world/type-values-places-and-borrow-views.md`
§2.1.1). After authorized
`Self_τ` back-references are erased, the owned graph must satisfy
`WellFounded_kappa`
(`spec/design/symbol-world/type-values-places-and-borrow-views.md` §2.1):
finite, acyclic, fully bound, and restricted to authorized static edge
kinds under static-eval generation (covering both compile and meta) and
acyclic once materialized at runtime.

Forbidden:

```text
TypeValueId equality implies PlaceId equality
SymbolId equality implies TypeValueId equality
PatternValue equality implies SymbolId or PlaceId equality
binding PlaceId determines struct PatternScopeId
a second name can be made to share another symbol's place
type-value equality grants write permission
root equality selects a current mutable Symbol or callspace
descendant classifier ownership implies TypeMember membership
```

Semantics of `let T: type = uint8`:

```text
symbol(T) = fresh symbol
place(T) = fresh writable place at current lexical level
type_value(T) = type_value(uint8)
```

There is no second declaration form with different place semantics. Every
binding allocates a fresh place; the frozen `let T === uint8` surface form has
no target semantics (see
`spec/design/symbol-world/entity-alias-design.md`). Where one place must be
observed through another name, the value held is a borrow view (`ref` / `share`);
`@` yields a first-class ordinary `LifetimeValue`, not a borrow. Transporting
that result does not execute `@` again.

Pure type-slot member creation names the place explicitly:
`let f::(T |> (type ref)) = ...`. For a Symbol `S`, use `let f::((S ref).type) = ...`;
`S |> type` is by-value and cannot recover a place. Navigation to a missing child yields the prospective ProjectionSlot
`(ParentPlace, Selector)` with contents `None`; `let` may instantiate it, while
ordinary `=` never creates it.

## 7. Borrow Views and Generic Arguments

Generic type-style meta-functions must distinguish query modes over an
argument. There is no alias chain to follow, but a borrow view is not the same
object as its target, so at least three query modes must be distinguished:

```text
type-value evaluation:
  read the value; a `type ref` / `type share` view reads through to its target

callable lookup:
  policy-aware symbol resolution; a view is its own value and its member set
  is not silently that of the target

member/write target:
  resolve the prospective or existing ProjectionSlot; let alone may create,
  while ordinary = requires an existing writable place

structural extension:
  read/clone the value, then independently check OpenHere_Σ(value)
```

Do not encode view transparency as a global boolean. A view behaves differently
in type-value position, callable target position, and extension-place position.

A borrow view must carry at least:

```text
target place
ordinary borrow lifetime relation
whether the view is `ref` or `share`
writability of the view (share carries none)
```

It must not contain `OpenWitness` or otherwise imply
`OpenHere_Σ(Value(target))`. `OpenHere_Σ(value)` and `Writable(place)` are independent
judgments. A closed-window pointee can remain readable and, through a writable ref, can
be wholly replaced by another legal value; it cannot be used as `extend` input.

No provenance chain, no forwarding chain, and no cycle detection are required,
because a view is one edge to a place, not a rewritable chain of symbols. Applying
a borrow operator to an existing view is a real overload that coerces capability
while preserving the target — `Borrow_k(Borrow_j(q)) = Coerce_{j->k}(Borrow_j(q))`
— which is *why* borrowing appears idempotent and never nests. Only `share ref`
has no candidate. Do not implement this as a chain to walk, and do not implement
the overlapping compositions as "no applicable overload".

### 7.1 Ordinary Value and Construction Kernel

All semantic collections remain ordinary PatternValues under
`Object = <Val1?, P, Val2>`. Implementations may use vectors or registries as
carriers, but those carriers do not define language identity.

Every well-formed Object has navigable `Val2`. Therefore:

```text
Pure(x) <=> NamespaceRole(x)
TypeRole(x) => NamespaceRole(x)
```

`TypeRole` is an imported relational judgment; the namespace-only
distinction is formalized via registered `ConstructEdge` in
`../design/patterns-overload/pattern-values-relational-semantics-and-extraction.md` §13
(`HasRegisteredSelfConstruction(Q)`), where the witness must be an actual
`Val2` member (`Val2(Q)[s] = K` together with `ConstructEdge_P_Q(C, Q, K)`).
This layer only consumes it
as an opaque predicate. These are judgments, not separate namespace/type Object
kinds.

The recursive closure is explicit:

```text
BareProduct(a_0,...,a_n)
  = <absent, P_bare_product, {pos_i -> a_i}> in Object

Seq_N(T; values)
  = <BareProduct(values), P_(T*N), GeneratedVal2(T*N)> in Object

Seq_omega(T; values)
  = <BareProduct(values), P_(T*omega), GeneratedVal2(T*omega)> in Object

ProductValue(values)
  = <BareProduct(values), P_product, GeneratedVal2(product)> in Object

Children_owned = Children_Val1 union Children_Val2
```

There is no `Children_product` or compiler aggregate beside `Object`; ordinal
Product elements are ordinary `Val2(pos_i)` children.

```text
T * N       finite homogeneous ordered; N is in type identity
T * omega   finite homogeneous ordered; length stays in Val1
bare Product  finite heterogeneous ordered; concrete fixed shape
product       finite heterogeneous ordered; outer shape erased only
```

The global privileged type-forming builtin `*` supplies `*(T,N) -> T*N` and
`*(T,omega) -> T*omega`. Both preserve element-type universe rank:
`rank(T*N) = rank(T*omega) = rank(T)`.

`T*N -> T*omega` is admitted. `T*N` and `T*omega` have mechanically generated
`[]` value/ref/share members. No contiguous layout, capacity, push operation, or
general runtime `product[]` is implied.

`symbol` is an ordinary type. Its mutable member content is:

```text
Σ = <tau?, V_S>
V_S = disjoint_union_{T_c} V_S[T_c]
V_S[T_c] : T_c * omega

Norm(Symbol)
  = < Norm_type(tau)?, { Norm(T_c) -> Set{ Norm(v) | v in V_S[T_c] } } >
```

`tau`, when present, is the complete type value carried by the Symbol;
namespace projection selects `Core(tau) = Q`, and type projection returns the
whole `tau`, optionally written `bind alpha.<Q,V_τ[alpha]>`. `Sigma` is itself
ordinary Object composition: the optional carried type value is an
empty/singleton bare Product holding `LowerTypeClosure(tau)`, every
`(T_c, V_S[T_c])` bucket entry is a `product` value, and the homogeneous entry
carrier is `product*omega`. The logical `<tau?,V_S>` view is not a
specification-private record. `LowerTypeClosure` is faithful and opaque
(symbol-first §4.7): lowered closures are equal up to `Norm_type`, and
ordinary Pattern/Object/Val1/Val2 semantics cannot observe extra distinctions
beyond the `tau` API.

Member/candidate objects carry stable declaration identity, callable-body
identity, and
selection-relevant declaration annotations survive. Only insertion order and
duplicate contribution of the same member are quotiented; conflicts are
construction diagnostics. A `symbol`-typed value `Σ` carries an optional type
value slot (`τ?`, `ShapeOfTypeSymbol`, glossary); when present, its installed
core is `Core(τ)`. The default meta result `τ_M = ⟨Q, V_τ⟩` is a complete type
value, so `Core` is total on it: `Core(τ_M) = Q` is always defined — a pair
projection, not a cardinality count. Its callable
val members project to the formal OverloadSet.

Construction operations are distinct:

```text
extend(type_value, material) -> type_value
  pure; OpenHere_Σ(value); no write; no new root; preserves root

inject(type_ref, material) -> type_ref
  Clone(Read(ref)) -> extend -> Write(ref); also requires Writable(target)
```

`type ref` is not valid input to `extend` and does not prove Open. `inject`
requires both independent judgments.

Borrow type values are universe fixed points (`type ref ref = type ref`,
`type share share = type share`,
`type ref rebind rebind = type ref rebind`, and
`type share rebind rebind = type share rebind`), with
`rank(type ref/share) = rank(type)`.
The former `@` fixed points (`type ref@ = type ref`, `type share@ = type share`)
and the former value-instance rule `t@ = lifetime(t)` are retired: `@` is a
continuation-relative name-reification operation that yields a first-class
ordinary `LifetimeValue` uniformly and is never a borrow constructor
(`lifetime-policy-and-overload-boundary.md` §1–§2.1).

A logical `ProjectionCoordinate(parent_place, selector)` is not the formed
borrow target. Projection borrows record
`ProjectionSlotIdentity=<ParentResidentIdentity,Selector>`, including when slot
contents are `None`. `let` changes one slot from `None` to `Some` without
retargeting; wholesale parent replacement creates new slots and invalidates old
borrows. Only `rebind` obtains a new target. Named and ordinal `pos_i` selectors
share this rule; `CanCreateMember(sequence,pos_i)=false`.
Sequence `IndexSlot(s,i)` is the ordinal ProjectionSlot under the resident
`Val1(s)` bare Product, not a direct `Val2(s)` navigation.

Borrow formation is explicit. Candidate adaptation, Policy migration,
structural repair, and automatic argument passing never rewrite an ordinary
Object/Symbol/type value into `ref` or `share`; fixed points and weakening apply
only after a borrow already exists.

`AsType(E) = E |> type` never raises universe rank; only explicit `TypeOf(E)` may
do so. In particular, `TypeOf(type) = type_1` and `TypeOf(symbol) = type`.

## 8. P1 and P2 Elaborate the Canonical Policy Pair

Canonical internal policy is:

```text
Π = Pv:Pp
PolicyMode = const | plain | mut
```

where `Pv` describes the value component and `Pp` describes its carried
Pattern/anonymous-type component. `PolicyMode` is a whole-slot coordinate
orthogonal to `Pv:Pp` and to `Val1` presence. Stage, value presence, ordinary
namespace visibility, export-root, and operation capability realization are
further typed orthogonal dimensions. A scalar policy is surface shorthand or
a derived summary only.

Surface elaboration must first factor at most one connected whole-slot
`ModePattern`, then elaborate the residual pair syntax. Neither side of `:` may
contain an independent semantic mode coordinate. A typed `ModePattern` is one
singleton `ModeAtom ::= const | plain | mut`. A surface `PolicyChoice` with
multiple ModeAtoms is invalid after factorization; in particular,
`const || mut` is not a neutral demand because the genuine neutral point is
`plain`. This restriction does not affect pair/view alternatives such as
`compile || runtime`. Whether a colon spelling left with an empty residual side
is rejected or receives a later contextual shorthand is a provisional surface
decision. This contract requires factorization and coordinate separation, not
the current provisional rejection list, and changes no frozen Raw/Norm AST
shape. In result-demand context, an absent ModeAtom defaults independently to
`plain`; it does not erase a residual choice such as `compile || runtime`.

Required presence invariants:

```text
Val1 = absent  =>  Pv = Pp
Pv != Pp       =>  Val1 != absent and runtime in Stage(Pv)
```

An observer may still hide an existing `Val1`, so `Pv = absent` is not evidence
that the object physically lacks one.

`P1` is the optional projection prefix on any binding:

```text
[P1] let x = e
```

Binding spelling first forms a concrete output-mode demand (`plain`, `const`,
or `mut`) and supplies it to RHS call selection as the output coordinate of the
same Policy product as all inputs. After unique RHS selection, omitted `P1`
retains the complete inferred pair result. A single `q` is a
value-dominant projection and retains the Pattern associated with every
selected value. An explicit `qv:qp` filters both components. Therefore the
single form `q` is not normalized to `q:q`. These lower-case policy
metavariables are distinct from the type-core `Core(τ)`.

General runtime binding remains legal:

```text
demand_mode = BindingDemand(prefix)
destination_mode = ElaborateDestinationMode(prefix)
Gamma; output_mode_preference=demand_mode
  |- e : (tau, Pv:Pp, produced_mode)
selected = ProjectP1(P1, e)
selected is non-empty
selected <= destination policy
TransferToDestination(selected, produced_mode, destination_mode, pass)
--------------------------------
Gamma |- [P1] let x = e
```

`produced_mode` remains the selected producer's concrete result fact.
`destination_mode` belongs to the binding slot. The transfer between them is
ordinary move/copy and must not be implemented as a PolicyMode rewrite.

For a nested call node `c`, `CallLocalPolicyClosure` requires its output
preference before `c`'s own maxima. That preference may use only an already
formed candidate-independent immediate-consumer demand; otherwise it is
`plain`. Once selected, `c.produced_mode` is frozen and the outer call consumes
it as an ordinary actual. An unresolved outer candidate may not back-propagate
its formal mode into `c`, and outer failure may not reopen `c`.

This total `OutputModeDemand(c)` participates in the PolicyMode product for
every call. Optional target-result pair/type/rank/facet constraints are a
separate `TargetResultConstraint(c)` and enter hard admissibility only when a
context actually supplies them; their absence never removes the output-mode
coordinate.

`PolicyLet(P, e)` is the explicit candidate-independent immediate-consumer
boundary. Agents must form `ResultPolicyDemand(P)` before selecting the root
call of `e`, then feed `SourcePolicy(result(e)) -> P` into the ordinary Policy
migration candidate preparation and unique Policy-overload selection, and expose
only the resulting concrete view through the node's ordinary expression-result
slot. That slot has its own concrete `PolicyMode` but is not a NameBinding,
Symbol, hidden declaration, or independently addressable Place. A producer
selected under `plain` preference may retain `produced_mode=const`; terminal
move/copy may be the selected migration's `ValueRealization` and install its
value under the expression-result slot's `plain` mode without rewriting the
producer. That same migration candidate supplies the coherent
`PolicyProjection`; no PolicyLet-specific Policy selector exists.
Agents must not lower the node to `e |> P`, a
Val2 `const`/`mut` call, a hidden declaration, or a transparent wrapper through
which an outer candidate can push a demand.

A source-side premise such as `Psrc != runtime` belongs only to the particular
compile-flow projection rule that states it. Agents must not move it onto
general `let` lowering or reject `binding_policy == runtime`.

`P2` describes the call/expression result pair. In P2 context only, a scalar
stage policy normalizes as:

```text
N2(P) = P:(P - runtime)        when P - runtime is non-empty
N2(runtime) = runtime:compile
```

An explicit P2 pair forbids runtime in `Pp` and requires any static stage in
`Pv` to agree with `Pp`. Function-object stage views are then derived from the
result pair:

```text
Stage(P1p) = Stage(P2p)
Stage(P1v) = Stage(P2v) union Stage(P2p)
```

This derivation applies only to stages. Result `PolicyMode`, namespace visibility,
and value presence do not propagate to the function object. An explicit P1 at
the declaration then projects the derived object view like any other binding.

The result remains layered `Object = ⟨Val1?, P, Val2⟩` material. There is no
scalar replacement for the result's `Pv:Pp` pair; the result slot still carries
its independent whole-slot `PolicyMode`.
Returned value/Pattern pairs retain their `Pv:Pp`; each returned `Val2` object
retains its own pair.

There is no independent full `P3`. Parameters inherit P2 and returns inherit
P1; either written position may refine only the independently inherited
whole-slot `PolicyMode` coordinate.
Stage, presence, visibility, and every other policy dimension are invariant.

The context-indexed candidate preferences are:

```text
succ_const: const > plain > mut
succ_mut:   mut > plain > const
succ_plain: plain > const = mut
```

`const = mut` in a plain context leaves both co-maximal and ambiguous when no
`plain` candidate survives. Preference never grants capability and never
means arbitrary selection.

Forbidden inference:

```text
symbol visible in compile lookup
=> callable entry executable as compile or meta
```

Correct inference:

```text
ResolveSymbol(path) succeeds
=> the Symbol identity exists independently of phase exposure

ExposePolicySlice(symbol, OpenStatic) exposes a meta/compile facet
=> the current static pass may inspect / classify / residualize that facet

current body-entry metadata admits Meta
=> meta pass may enter / evaluate callable body
```

For ordinary generic type-style meta-functions, the minimum requirements are:

```text
the normalized P2 result pair is meta:meta
the derived function-object stage view contains meta
callee payload is callable/meta-callable
implicit self and explicit arguments satisfy their declared pair patterns
public meta return default is `τ`; target core/root validity is
checked inside construction (current TypeFacet/NamespaceFacet fields are caches only)
returned layers retain their component policy pairs
returned Val2 objects retain their own policy pairs
```

The current implementation does not expose this final source model. It stores
symbol policy, `body_entry_policy`, and `return_object_policy` metadata. Agents
must preserve those fields where current code depends on them, but must label
the return-object field transitional and must not treat it as a whole-result
policy slot.

The current branch includes typed structural compile-flow projection and
derived-companion exposure substrate. End-to-end evaluator integration,
must-select enforcement in every call path, automatic require, and complete
graph-wide pair storage remain incomplete.

## 9. Generic Meta Instance Identity

Ordinary generic type-style meta-functions must have a canonical meta instance
key. Source text or normalized dumps are forbidden as the only identity.

Every canonical argument must be `GlobalKeyable` at key-creation time. A
caller-local binder is not itself forbidden, but every global-key dependency
must be `AlreadyGlobalStable` or `AlreadyPromoted`; a future promotion at an
enclosing seal does not qualify. Global-key dependencies include horizontal
borrow targets even though owned normalization and promotion exclude those
edges. Thus `GlobalKeyable(Borrow(q))` requires an already globally stable `q`.
`compile` and transparent construction intrinsics do not create this boundary
and may consume meta-local PatternValues without promoting them.

Meta-local PatternValues have `MetaInvocation` lifetime. Ordinary meta-body
events do not freeze them, but transparency is not global escapability. At seal,
the default result `τ_M` promotes its `OwnedResultClosure(τ_M)` —
`OwnedClosure(Core(τ_M))` plus `OwnedCallSpaceClosure(CallSpace(τ_M))`, symbol-first §4.3.2.
An explicitly `symbol`-typed result promotes the carried `τ`'s owned result
closure only when `τ` is present. `EscapeDeps(τ)` covers the whole returned
result at the τ level (`Core(τ)` ∪ `CallSpace(τ)`) plus every horizontal borrow
target; at the Object level it walks `Val1`/`Val2`. Every escape dependency must
be already global or in the promoted result closure (only already global when an
explicit `symbol` result carries no `τ`). The promoted
closure follows direct owned parent-to-child transitions only; bare/external
leaves terminate expansion, external subtrees cannot re-enter, and cycles are
forbidden. `compile`
transports existing values and lineages but creates no global Pattern root.

Minimum key:

```text
callee function SymbolId
canonical argument product
canonical argument identities by parameter rank:
  symbol -> SymbolId / observed PlaceId
  type   -> default Core(tau)=Q observation, exactly as the old `type = Q`
            rules did; `TypeValueId` is the implementation/index projection,
            not semantic equality; whole-snapshot Addr(Norm_type(tau))
            identity applies only where the language has independently
            frozen it
  value  -> PatternValue identity
package identity
mount identity if relevant
build/config fingerprint
policy/export/provenance-relevant metadata
```

Examples:

```text
key((T Vec)) =
  SymbolId(Vec)
  + ArgProductShape([TypeSymbol(T)])
  + build/config fingerprint

key((A, B Pair)) =
  SymbolId(Pair)
  + ArgProductShape([TypeSymbol(A), TypeSymbol(B)])
  + build/config fingerprint
```

Product canonicalization must happen before key computation. Exposed Products
must be flattened in order; Expression barriers must not be crossed; whether
`Unit` participates in the key must be defined by the `ProductObject` contract,
not guessed by implementers.

The complete invocation is one navigation atom. If the callee is `Vec::std`,
the instance is `(T Vec::std)` and a child is `child::(T Vec::std)`. The forms
`(T Vec)::std` and unparenthesized `T Vec::std` do not denote that instance.

An ordinary canonical meta invocation also establishes a virtual construction
scope:

```text
M = MetaInstanceScope(callee_symbol, canonical_arguments)
```

Generic construction anchors through the same symbolic relation:
`MetaInstance(MetaPartner(F), Norm(GenericArgs))` keys the instance by the
callee's declared meta partner and normalized generic arguments, and a
generated closure's type is rooted at that scope
(`ClassifierRoot(TypeOf(C_F,A...)) = M`). Generated meta partners are not
ordinary meta functions (canonical owner
`spec/design/meta-invocation/meta-object-invocation-and-policy-reduction.md`
§4.4).

For the default result `τ_M`, `Pure(Core(τ_M))` holds unconditionally and its
outer Pattern root is `M` (`Root(Core(τ_M)) = M`), because `Core(τ_M)` is the
first projection of `τ_M`. For an explicitly `symbol`-typed result that carries
a type core `Core(τ)`, the same `Pure(Core(τ))` and `Root(Core(τ)) = M` hold
when `τ` is present. `TypeRole(Core(τ))` is required only for type projection,
not for the generic meta-root rule.
Direct meta type returns `r = t` and `r = uint8` are therefore invalid when the
right side is an externally rooted `PatternValue`. This requirement does not
apply to `compile`, which creates no `MetaInstanceScope` and may return an
existing type value directly.

## 10. Meta Expansion and NamespaceDelta Atomicity

Any meta symbol construction must be installed through a transaction-shaped
result. A `compile` invocation computes an ordinary semantic value across
result classes and does not itself install a `Symbol` constructor value or
namespace delta.

The invocation and binding layers carry distinct materials:

```text
PatternValue:
  compile-time value / type value / structured pattern value

Meta construction carrier from ordinary meta
(current substrate: SymbolConstructionValue):
  transport for an ordinary default `τ` result's member material, not a result class
  symbol/member/pattern construction material
  non-root assigned value/member may equal an existing PatternValue
  default τ_M: Core(τ_M) root equals its canonical
  MetaInstanceScope (construction invariant);
  explicit symbol result: carried Core(τ) root, when present, equals the
  same canonical anchor
  resolved pattern owner
  diagnostics provenance
  construction identity material

Binding/install adapter (current substrate: MetaExpansionResult):
  replacement_object
  namespace_delta
  diagnostics
  provenance
  cache_key_fragment
```

The target terminology is:

```text
DefaultMetaResult = τ
MetaInstance(M) -> τ_M
ShapeOfTypeSymbol(v) = <tau?, V_S?>   -- shape of a `symbol`-typed value only
```

An explicit `f : … -> symbol` is still legal. Presence or absence of `tau` and
`V_S` are content facts within that
`symbol`-typed value, not result categories or extra facets. When `tau` is
present, its core `Core(tau) = Q` is the canonical namespace object of the
Symbol; `TypeValueRole(tau)` (equivalently `CompleteType(tau)`) implies
`TypeRole(Core(tau))`, so `Q` is self-rooted at the MetaInstance. A
namespace-only `tau` — well-formed with `NamespaceOnly(Core(tau))`, i.e.
`NamespaceRole(Core(tau))` and not
`HasRegisteredSelfConstruction(Core(tau))` — has the same presence condition
for the self-root: the condition is `Q`'s presence, not `TypeRole`. A `Symbol` constructor value with `<None, V_S>` has no
installed type core by sibling count.

Rules:

```text
success:
  install replacement and namespace delta as one unit

failure:
  install no generated symbols
  retain diagnostics
  leave no partial generated namespace subtree
```

This rule applies to:

```text
struct
(T Vec)
(T Option)
(A, B Pair)
future meta symbol constructions
```

Forbidden:

```text
formal struct directly installing graph state
binding target rerooting an already resolved pattern owner
installing a half-generated type object and adding field functions later
leaving a partial type-associated namespace after failure
letting diagnostics depend on half-installed graph state
```

## 11. `struct` Must Migrate Toward Shared Meta Invocation

The current `struct` path may exist as a vertical slice, but new ordinary
generic type-style meta-functions must not expand that bespoke path.

Target direction:

```text
current struct / verify path
  -> shared meta invocation client

resolve callee
collect candidates
match ProductObject / ArgShape / TypeSymbol
check current body-entry metadata / future stage and parameter-pair rules
invoke primitive or interpreter
produce the complete type value `tau`, possibly through the transitional carrier
materialize binding/install adapter
install delta atomically
```

The `struct` payload may be primitive. Its lookup, argument parsing, policy, and
delta installation must not split into a separate mechanism from ordinary
generic type meta-functions.

`struct` must form a complete type value `tau` whose core `Q_struct = Core(tau)`
satisfies `Pure(Q_struct)` and `TypeRole(Q_struct)`, plus its
mechanically generated partner families entering `V_τ` when the closure is produced.
A `Symbol` constructor value appears only at a subsequent binding/install of the formed value.
Accessor stage follows only:

```text
RuntimeField(f)
  iff Val1_f != absent
  and Materializable_0(Val1_f)
  and not RequiresStaticPattern(f)
```

Runtime fields expose runtime-or-compile accessors; every other field is
compile-only. Type is not a special field category. Generated Sequence `[]` is
a bounds-domain partial projection over ordinal `ProjectionSlot`s and its stage
is the ordinary meet of container, index, and selected-observation dependencies;
`RuntimeField` is only the selected-element condition. Open authority does not propagate along owned field relations; each
PatternValue's `OpenHere_Σ` is determined independently by stack-relative
authority-frame resolution (canonical §12.1.1). Mutability does not propagate.

Field/access/ref/share/assignment partners belong to the complete type
snapshot. Copied/extracted type-as-callee lookup is `CallSpace(tau)=V_τ`;
`HomeSymbol(TypeValue)`, defining-Symbol recovery, and recent-carrier
provenance are retired.

Ordinary associated installation is never structural registration:

```text
Val2(c)[s] = y !=> DirectPatternChild(P(c), c, s, y)
ordinary navigated let -> Val2 member only
struct / extend       -> may register a direct structural child
inject                -> obtains that privilege only through extend
```

The canonical Pattern judgments and callable-role boundary are owned by
`spec/design/patterns-overload/pattern-values-relational-semantics-and-extraction.md`.

The current PR #94 context-attachment helper and
`GeneratedTypeDefinitionValue` fallback are transitional registry substrate.
They do not implement `ResolvedPatternScope`, binding-independent owner
resolution, the ordinary Symbol result, pure `extend`, or place-level `inject`.

   feature.
7. When handling generic type-style meta-functions, assume by default that
   `struct`, `(T Vec)`, `(T Option)`, and `(A, B Pair)` ultimately belong to the
   same shared meta invocation frame.
8. When handling product arguments, use the rule: exposed Products flatten in
   order, Expression barriers are not crossed, `Unit` is not dropped, and
   provenance is not dropped.
9. When handling policy, keep `P1` binding projection distinct from `P2`
   result-pair normalization, derive function-object stage views from `P2`,
   and preserve current result-policy metadata only as transitional transport,
    not a full `P3`; returns may still refine inherited P1 PolicyMode only.
10. When handling shared observation, use borrow views: one view is one edge to
    one target place, `Capability(view) ⪯ Capability(source)`, and there is no
    alias transparency to classify by usage.
11. When handling meta returns, keep current `r = ...` accumulation explicitly
    transitional; target semantics use the default `τ` result, ordinary existing-
    place writes, and a separate return event. Never reintroduce `r === ...`.
12. When handling `struct`, keep `pattern_owner(V)` independent from
    `install_place(V)`. Pure `extend` requires an open by-value type; place-level
    `inject` additionally requires a writable `type ref`, which never proves
    Open. There is no owned/uninstalled construction-handle rank to pass around.
13. When handling ordinary-meta results, require the return self-root to equal the
    ordinary-meta canonical `MetaInstanceScope`; do not accept identity-style
    `r = t`.
14. When handling namespace contributions, preserve one `NamespaceOrigin` and
    one construction owner per created subtree; do not reopen it across files.

Minimum acceptance standard:

```text
An agent's plan must mention:
  ProductObject / ArgProductShape
  SymbolCell (or current SymbolObject substrate)
  PatternValue / TypeValueId / PlaceId / BorrowView
  meta-construction carrier / ResolvedPatternScope
  canonical Pv:Pp, P1 projection, P2 normalization, plus transitional metadata
  canonical meta instance key
  NamespaceDelta atomicity
  no-bypass rule
```

If these terms do not appear, the plan has not absorbed this construction
document.
