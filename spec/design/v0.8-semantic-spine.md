# v0.8 Semantic Spine: Symbolic Construction Values and Extraction

**Status: Future design narrative for value/extraction behavior. Not current
implementation behavior.** The old formal meta-return split in this document is
superseded by
`spec/design/symbol-world/symbol-first-meta-construction-and-pattern-injection.md`,
which is the canonical first read for symbol construction, `compile` / `meta`,
pattern ownership, `struct`, and `inject`.
Namespace origin and source/meta construction ownership are canonical in
`spec/design/symbol-world/symbol-construction-units-and-namespace-origin.md`.

---

## 1. Values First

An evaluation returns one result object, whose normal form may be an ordinary
value `e` or a product value `P`:

```text
e:
  ordinary non-product value point

P:
  product value / product normal form
```

A meta constructor call returns a `SymbolConstructionValue`:

```text
(int Vec::std)
```

This is not a `TypeValueId`. It is the value formed by the construction
expression `(int) |> Vec::std`. Type computation is only one projection of that
value, not its definition.

**Notation.** This document uses `(int Vec::std)` as the complete canonical
meta-instance navigation atom and `(int) |> Vec::std` as the pipe/call skeleton
from which it is derived. The callee path remains inside the invocation
parentheses. Neither `(int Vec)::std` nor unparenthesized `int Vec::std` denotes
that instance.

## 2. The Hourglass

Every construction value is a waist point:

```text
        extraction pattern space
              ↑
              |
        construct / extract
              |
              ↓
          value point e
              |
              ?
              ↓
        exposed extraction view e' or P
```

Upward: the value participates in a constructor-specific isomorphism
(`construct_C(P) = v`, `extract_C(v) = P`).

Downward: `?` enters the value's currently exposed extraction view.

## 3. `?` Enters One Extraction View

`?` does not mean "destructure." It means "enter one exposed extraction view."
Destructuring happens only when a pattern matcher consumes product normal form.

```text
leaf e:
  e? = e

non-leaf e:
  e? = peel_one_exposed_extraction_view(e)
  // result may be e' or P

product P:
  P? = P
```

This view may be constructor-declared, but bare `?` is not the
constructor-specific inverse extractor. The upward `construct_C` / `extract_C`
isomorphism and the downward `?` view transition are separate paths. Extracting
a type parameter (for example from `Vec::std`) requires the constructor-specific
extractor in a rank-pattern context, not bare `?`.

`?` is not recursive by default — it peels one declared top pattern layer. It
does not keep peeling until a target pattern is found. It does not perform Error
propagation. Multi-layer or recursive peeling must be explicitly defined by the
type / extraction interface.

The minimal sum-pattern example is `bool` (see
`return-value-extraction-and-implicit-decomposition.md` and
`static-pattern-spaces-and-extraction-chains.md`§9): `bool_cond?` produces the
closed sum pattern space `if | else`. Cond-oriented operators may return the bare
branch pattern directly, and wrappers may define custom `?` to expose a chosen
view in one step.

`(int Vec::std)? == (int Vec::std)` — the construction value is a leaf in
ordinary value context, so `?` is idempotent.

Equality never inserts `?`. Binding context may request one pattern-directed
`?`.

This is future extraction-view semantics, not the next implementation
milestone. Early extraction-pattern work must first build the shape substrate:

```text
NormPattern / let-left material
  -> ExtractionPatternTree
  -> HoleCapture list
  -> ResolvedPatternHead list
  -> well-formedness diagnostics
```

That milestone must not execute RHS extraction, request pattern-directed
implicit `?`, recursively peel values, implement Done / residual / sum
exhaustiveness, or integrate access-tree checking.

## 4. Product Return and Non-Product Return

For product return:

```text
let P = () |> two_return;
P == (a, b);              // result is product normal form
P? == P;                  // product normal form has no shell to peel
let a, b = P;             // product binding consumes P directly
(a, b) == P;              // true
```

For non-product value `e`:

```text
let e = () |> single_return;
e? == e;                  // if e is leaf
let a, b = e?;            // error if e? is still leaf
(a, b) == e;              // false if e is not product normal form
```

For a non-leaf construction value `e` with an exposed product view:

```text
e? == P
P == e?                   // true
P == e                    // false
P A== e                   // true under named constructor / pattern A
```

`A==` is provisional notation for constructor/pattern mediated equality. It is
not ordinary value equality.

Binding may request `?` only as pattern-directed repair:

```text
let a, b = e              // may try `let a, b = e?` if direct binding fails
```

## 5. Compile Computes Values; Meta Constructs Symbols

This narrative depends on, but does not redefine, the canonical split:

```text
compile -> PatternValue
meta    -> SymbolConstructionValue : symbol
```

`compile` is value-level staging; `meta` is symbol-level staging. The exact
`MetaInstanceScope`, return-slot handle, type self-root, rank-directed identity,
and formal-return rules belong solely to
`symbol-world/symbol-first-meta-construction-and-pattern-injection.md`. This
spine uses their results when describing value and extraction flow.

## 6. Invocation Returns an Uninstalled Value; Binding Installs It

The future invocation layer produces one of:

```text
PatternValue
SymbolConstructionValue
runtime value
Residual
Diagnostic
```

The expansion/binding layer consumes the value and installs graph/world state
only when the declaration form requires it (`NamespaceDelta`, symbol binding,
facet exposure, and result-symbol lookup-policy inheritance from callable
`P1`). Result layers retain their own policy; there is no independent `P3`.
For symbol construction it
must keep `pattern_owner(V)` distinct from `install_place(V)`; a binding target
does not reroot the construction's pattern owner.

The current `MetaInvocationResult` / `MetaInvocationValue` and binding APIs are
transitional transport. They do not implement the canonical result objects,
meta-instance identity/self-root validation, namespace origin, or construction
ownership.

`IdentityType` proves invocation plumbing. It does not prove final meta type
construction, `MetaInstanceScopeId`, or return type self-root validation.

## 6.1 Control-Flow-Local Meta Evaluation

Branch-local guarded evaluation rests on four cornerstones (see
`static-pattern-spaces-and-extraction-chains.md`§17): sum patterns for
branch-selection material, simple type check for branch-local type facts, simple
policy check for branch-local capability facts, and symbol-space construction and
lookup for branch-local names. The central invariant is that only the selected
branch may perform lookup, policy check, meta invocation, or local symbol
construction; unselected branches have no obligation of any kind.

That selected-branch rule applies after a compile-policy scrutinee is known.
Compile-flow projection retains the Pattern of runtime symbols, and automatic
require represents every runtime-reachable branch as a pattern-guarded
contract. See
`symbol-world/symbol-policy-and-compile-flow-projection.md`.

## 7. Implementation Guardrails Follow From This Spine

The implementation invariants (closed loop, no-bypass, ProductObject,
ArgProductShape, symbol/place/type-value separation, current policy metadata,
future `P1` / `P2`, canonical
meta instance key, NamespaceDelta atomicity) are consequences of the semantic
model above, recorded in:

`spec/contracts/v0.8-meta-construction-agent-constraints.md`

`ProductObject` and `ArgProductShape` describe only the explicit user-supplied
argument product. Function-object self is injected by the invocation frame into
callable-frame slot 0 and must not be added to product shape or canonical meta
instance keys.

## Implementation Substrate Note

The v0.8 build substrate represents return normal form explicitly:

```text
EvalResultNormalForm = ValuePoint(e) | Product(P)
```

The `question_view` operation is shape-level and pure:

```text
Product(P) -> Product(P)
leaf e     -> e
non-leaf e -> exposed view
```

Generated struct type materialization records a queryable named field extraction
interface for instances of the type. That interface belongs to the materialized
`TypeObject` metadata, not to graph installation performed by formal `struct`
invocation. The current invocation path may allocate registry-backed pattern
material, so its precise guarantee is graph-installation-free/binding-free, not
unconditional purity.

Binding may request one extraction view as pattern-directed repair. Equality and
ordinary expression evaluation do not request `?`.

Implementation status: implicit pattern-directed `?` is not part of the
next-stage `ExtractionPatternTree` / `HoleCapture` substrate. The current
substrate should preserve explicit value-to-pattern boundaries and stop at
pattern-head and hole-capture well-formedness diagnostics.
