# 规范验收矩阵

本表规定目标行为，不是已执行的 lang 测试报告。每行的正例与反例必须成对处理；API 名称为示意时，实施者先按对应 owner 确定普通注册接口。

条款引用来自 [canonical owner/ledger](lifetime-concurrency-consolidation.md)。各行的 D 表示目标已在 owner 定义；P/S/C/T/B 的 — 表示完整场景的证明/源语法链/语义链/正反执行/后端尚未完成。单个既有 token/carrier 或有限模型不填为该完整场景的完成证据。局部已执行项另见 ledger；只有真实完成后才能更新对应项。下方附件模型证据另列，不替代这些验收。

## 已有有限模型的实际证据

[unaltered bounded model](evidence/lifetime-concurrency/expressiveness_checks_v0_1.py) 为用户附件中的原始有限模型，未改动代码。它只是当前设计的表达力辅助材料；其注释中的说明性语汇不是 lang 新本体或源码规范。

本次用 Python 运行得到：

Mutex: 8 reachable states, 8 transitions; one-owner invariant HOLDS
Slot: 8 reachable states, 8 transitions; exact-once transfer invariant HOLDS

Negative: unlicensed count decrement breaks ARC; peek-only lock acquire duplicates guards
NOT CHECKED: fence ISA behavior, IRIW, OOTA, overflow, weak refs, reclamation, compiler lowering

进程退出码为 0，输出与附件的预期文本逐字一致。交付包此前没有运行 lang 仓库测试。本轮仓库命令另见 [实际记录](lifetime-concurrency-consolidation.md#actual-verification-record)；源代码消费者仍未接通。

## 测试实施纪律

在首次连接相应语义前，既有不可用诊断应保持明确而可定位；不能以任意空值、NoDelta、默认 root、改 ABI 或候选重试冒充正例。

测试应由实际来源形成名字、伙伴、权利、提交和边界映射。fixture 直接灌入一个 ready/valid 位，只能测 carrier 的局部行为，不能作为 source-produced 正例。

未封闭的 SeqCst/fence 选择单独标记；标准非根 Pool 普遍保证迁移已是必须满足的能力，不能因实现困难而降格为逐次尝试。CI 通过也不能覆盖表中证明门槛。
